### What the game is
Ultra Deep Field: a space-empire strategy game for friends and family. One HTML file (`docs/index.html`, ~4 MB: CSS, JS, three.js r128 3D, inline art) served by GitHub Pages from `main` (a push to `main` is a deploy), installable as an app, synced through Supabase. A copy runs as a claude.ai artifact (https://claude.ai/artifact/YSphcWgn5cKuSSYNPhD8hP). The owner (account "IH IY IP IE IO N IE") designs it, paints the art and tests on a Galaxy Z Fold 6 and an iPhone.

### How changes are made (keep doing it this way)
- Every change is a Python patch script in `tools/patches/pNNN_name.py` (sometimes with a `.js` part beside it) that string-replaces exact text in `docs/index.html` and asserts each replacement matched once. Patches are applied in version order; each bumps `GAME_V` from N-1 to N.
- Release, every time: apply the patch to `docs/index.html`; bump `CACHE` in `docs/sw.js` (udf-vNNN) and `docs/version.json`; add an entry at the top of "Pending work" below (format `00000000000000000000000000. **vNNN — title** (patch; owner request). what changed, where`) and update the header lines; check the patch reproduces (`git show main:docs/index.html > r.html; python3 tools/patches/pNNN.py r.html; cmp r.html docs/index.html`); `node --check` the main script; branch `vNNN-name`, commit, `git merge --no-ff` into `main`, push both; then `python3 tools/to_artifact.py docs/index.html art.html` and publish that to the artifact URL with label "Version NNN".
- Commit trailers used so far: `Co-Authored-By:` and `Claude-Session:` lines (a new tool will have its own).
- Test before telling the owner something works: build an offline copy (`tools/dbg_build.py`, or the harness described under Testing), serve it on localhost, drive it with Playwright (`window.__dbg.ev(code)` runs code inside the game's scope), and look at screenshots at phone size (430x932, DPR 2). Headless WebGL is SwiftShader: slow but correct.

### The Advisor's voice
New Advisor lines need clips: compute each line's key (`hash(line).toString(36)`, the game's FNV-1a), add `{key, where, line}` entries with `python3 tools/voice_add.py new.json`, push, open `docs/voicelab.html` in a real browser (it runs the Kokoro model on the GPU), "Load model" then "Make only the missing lines"; it downloads a zip of WAVs. Convert each with `ffmpeg -i k.wav -af loudnorm=I=-19:TP=-1.5 -ar 32000 -ac 1 -b:a 56k docs/voice/k.mp3` and set `index.json[k]=1`. The game plays a line if its key is in `docs/voice/index.json`.

### Server
Supabase project `slubtpfnimxtrfcozvhk`. Edge Function `settle_fight` (`supabase/functions/settle_fight/`) re-runs boss fights with `sim.js`, the battle simulator cut from the game by `tools/sim_bundle.py` (`THREE_JS=<three.min.js> python3 tools/sim_bundle.py`). The deployed function imports `sim.js` from jsDelivr pinned to a commit (now e7785259…, game v515, battle rules v6); after any change to `simulate`, unit stats (AL/SH/DF), CPROF or RF, rebuild `sim.js`, push, and redeploy with the import pinned to the new commit. It only logs agreement in `fight_log` (phase 2); nothing depends on it yet.

## What this is
A space empire strategy game ("the GitHub version"), played by friends and family as an installable web app. There is also an older claude.ai artifact copy of the game; this repo is the website build.

- **Live site:** https://gunhypechannel.github.io/Ultradeepfield/
- **Repo:** https://github.com/gunhypechannel/Ultradeepfield (the old lowercase `ultradeepfield` URL redirects; use the new one as `origin`)
- **Hosting:** GitHub Pages serves `docs/` from `main`. A push to `main` is a deploy (live in ~1–2 min).
- **Server:** Supabase project "Ultradeepfield" (`slubtpfnimxtrfcozvhk`). The old Firebase project (`udf-ultra-deep-field`) is the fallback only if `supabase-config.js` isn't filled in.
- **Main test device:** Samsung Galaxy Z Fold 6, usually unfolded (CSS viewport ≈ 884 × 1030 at DPR ~2.1).

## Layout
| Path | What it is |
|---|---|
| `docs/index.html` | The whole game (~2 MB, one file: CSS + JS + inline art). Version notes are comments like `/* v207: … */`. |

| `tools/` | Playwright tests against mock servers (`mock-supabase.js`, `mock-firebase*.js`) and an icon generator. |

## How saving works
- The whole empire (`S`: resources, buildings, research, ships, **fleets in flight, stationed guards, timers**) is one JSON blob saved to `data/users/<uid>/save` with `seq`, `sess` (per-tab session id), `savedAt` and a signature.
- Shared world data (planets, players, alliances, joint strikes) lives in separate docs and syncs live.
- **Since v293** the cloud save leaves out `reports`/`savedReps` (`repsSep: 1`); they live in `data/users/<uid>/reps`, written only when they change (before the save). `repsInto` merges them on sign-in and in `adoptCloud`. localStorage still holds the full state.
- **Since v293** private records (`data/...`) are not on the live channel (`filter: "top=neq.data"` in `udf-supabase.js`). The account save is polled every 30 s while visible (and on return to the tab) as just `updated_at, seq, sess, savedAt` (`dataSnap`), which is all the hand-off listener needs. Background saves reach the server at most every 20 s; actions, hiding and leaving still save at once.
- Hourly/daily backups go to `data/users/<uid>/backups/`.
- Device-only settings (audio, graphics, key bindings) stay in `localStorage` per device on purpose.
